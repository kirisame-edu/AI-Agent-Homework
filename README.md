單元0任務:建立產品客服 Agent 的初步構想與使用場景

## 背景

家中經營一間半導體製程設備與耗材相關的技術服務公司,主要業務包含 ALD 鍍膜代工、MOCVD 設備移機與保養、自動控制整合設計、硬脆材料設計加工、設備與特用材料銷售等,客戶多為半導體廠、研究機構與大學實驗室的採購或工程人員。

## 問題:為什麼需要這個 Agent

一開始想的是做一個「回答客戶問題」的對外客服機器人,但仔細想過後,發現真正卡住效率的地方,其實是**信件量太大、太雜,追蹤不過來**,而且往來方向有兩種:

1. **對外(客戶方向)**:客戶來信詢價、問服務項目,由經營者回覆報價或說明
2. **對內(採購方向)**:公司要採購原物料/設備時,由經營者主動寫信詢問其他供應商報價,對方回覆,再確認或議價

這兩種信件混在同一個Gmail信箱裡,常常造成:

- **忘記自己有沒有回過**:某封信到底回了沒、回了什麼,得靠翻信件回想,很花時間
- **案子進度不透明**:一個採購案或客戶詢價案,可能來回好幾封信,但沒有一個地方能一眼看出「現在卡在哪一步、輪到誰回覆」
- **對外和對內的信混著看,容易搞混**:同樣是"詢價",有時候是被問的一方,有時候是主動問別人的一方,角色不同但處理方式類似,容易看錯狀態

比起做一個給客戶用的聊天機器人,**先把Gmail裡的往來紀錄整理清楚、能被查詢**,才是真正能提升工作效率的**真實需求**,而不是為了交作業而做的題目。

## Agent 初步構想

一個讀取Gmail歷史紀錄、整理與查詢「業務往來進度」的助理型Agent,功能設定如下:

1. **讀取Email往來紀錄**:讀取Gmail中與客戶/供應商的往來信件,依「案子」(同一個客戶或同一次採購詢價)分組整理。
2. **建立客戶/供應商名單**:從往來信件中自動整理出聯絡人資訊(公司名稱、聯絡人、Email、身份是客戶還是供應商、往來次數),累積成一份可查詢的名單,取代目前只能靠印象或翻信件回想「這個人是誰、之前談過什麼」的狀況。
3. **標記往來方向與角色**:區分每封信是「客戶詢問我方」還是「我方詢問供應商」,避免兩種情境混淆。
4. **回覆狀態追蹤**:針對每個案子,標示目前狀態(已回覆/待回覆/等待對方回覆),並記錄最後往來時間。
5. **自然語言查詢**:可以直接問「OO公司那封信回了嗎」「上次問XX供應商的報價案進度到哪」,Agent 依紀錄回答,不用自己翻信件。
6. **待處理清單彙整**:定期彙整目前所有「待回覆」的信件清單,依急迫程度排序,提醒優先處理。

## 使用場景範例

- **場景A**:想確認某位客戶上週寄來的詢價信到底回覆了沒有 → Agent 查詢紀錄,直接告訴該案的處理狀態(已回覆/待回覆及時間),不用再翻信箱大海撈針。
- **場景B**:公司要採購一批原物料,半個月前寫信問了三家供應商報價 → Agent 彙整這三家的回覆狀態,告訴哪幾家已回報價、哪幾家還沒回,方便決定要不要催促或改問其他家。
- **場景C**:每週開始工作前,想快速掌握有哪些信件還沒處理 → Agent 主動列出「待回覆清單」,依信件到達時間排序,可以照優先順序一一處理,不會漏掉重要客戶或錯過報價時效。
